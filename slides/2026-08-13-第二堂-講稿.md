**講稿**：這一段是今天的核心動作：規格是人寫的，code 是它產的。
「先複述你的理解」那句是保險 —— 讓它在動手前把誤解講出來，
省下的時間比它花的多。現場示範一次它複述錯、被我糾正的樣子最有說服力。

看 diff 不是要他們讀 code，是看「它動了哪幾個檔」——
動到你沒要求的檔案就是警訊，那時候退回去重講。

額度要老實講：免費約 10 次/天，反覆試錯很容易用完。有 Plus 的人會順很多，但不要讓沒付費的人覺得今天做不完 —— Plan B（普通對話 + 貼回 GitHub）是真的可行。

## Slide 18

想法落在哪一層，就叫 AI 動那一層
你不必知道要改哪個檔 —— 講你想看到什麼就好
18
| 你的想法 | 落在 | 你就這樣跟 Codex 講 |
| 畫面上的字、顏色、按鈕 | ① 頁面 | 「送出按鈕的字改成『幫我整理』」 |
| AI 回答的內容或格式 | ③ 伺服器 | 「回答多一欄負責人，沒寫就填未指定」 |
| 要記住上次打了什麼 | ⑤ 資料庫 | 「我要記住上次打的，該加什麼？」 |
說得出「從什麼變成什麼」→ 直接講，這叫具體
不知道該動哪裡 → 先問路：「我要 ___，該加什麼？」，這叫抽象

**講稿**：這頁是整份 deck 最實用的一頁，因為它回答「我有想法之後第一步做什麼」。
抽象與具體的分工要講清楚，但都用他們的語言講 —— 台下不會有人去打開檔案：
· 具體 = 你說得出「原本長這樣 → 我要它變那樣」。直接講，它自己去找檔案。
· 抽象 = 你只知道想要什麼、不知道要動哪裡。那就問路，讓它告訴你該加什麼。
兩個反過來都會壞：什麼都還沒想清楚就下具體指令 → 你會指錯方向；
一直抽象 → 它到處亂改，而且一個 Codex task 就燒掉了。
現場示範：拿「我要記住上次打什麼」問一次抽象的，看它自己說要加資料庫。
它動完會回報改了哪些檔 —— 那時候看一眼就好，這就是驗收，不是要你讀 code。
口頭再補兩條（版面放不下）：
· 「不想被別人看到我的資料」→ 落在 ⑤ 的 RLS，不是 ① 頁面 —— 頁面擋不住任何人。
· 「我要每天早上自動跑一次」→ 落在 ② GitHub，就是第一堂那個競品監控器。

## Slide 20

Chatbot 跟 Agent 差在呼叫幾次
今天做到哪一步，我講清楚，不含糊
20
|  | 今天做的 | 完整的 Agent |
| API 呼叫 | 一次 | 多次，它自己決定要幾次 |
| 「自我檢查」 | 同一段輸出裡自己說「我不確定 X」 | 真的跑第二輪驗證第一輪 |
| 工具 | 沒有 | 自己呼叫工具查資料、讀檔 |
| 下一步 | 你決定 | 它看上一輪結果決定 |
今天裝的是骨架：角色 ＋ 判斷規則 ＋ 自我檢查
讓它自己跑多輪（五層裡的 ❹ Loop）是下一步 —— 今天不做，但你要知道差在哪

**講稿**：為什麼要誠實講這頁：prompt 裡寫「做完檢查有沒有遺漏」不會讓它變成 Agent，它只是在同一次生成裡多講幾句話。Anthropic 的定義是「LLM 動態決定自己的流程與工具使用」——一次呼叫的結構化輸出叫 workflow，不叫 agent。

這頁也讓 deck 內部一致：後面五層那頁標了「❹ Loop 還沒做」，而 Loop 正是 Agent 的核心。兩頁不能一頁說沒做、一頁說做到了。

有工程背景的學員會問這個 —— 誠實講你站得住腳，而且他們會更信任後面的內容。

## Slide 21

Agent 零件①：角色設定
21
跟 Codex 說：把 AI 的角色設定換成這段 —
 
你是一位嚴謹的會議秘書。
把使用者貼進來的筆記整理成三類：
待辦事項 / 已做的決議 / 需要再確認的事。
用表格輸出，欄位是「類別 | 內容 | 負責人」。
沒寫負責人的填「未指定」，不要自己猜是誰。
不確定的放進「需要再確認」，不要編。
「不要自己猜」「不要編」這兩句很重要 —— 不寫它就會編

- 沒寫負責人的填「未指定」，不要自己猜是誰
- 只根據我貼的內容，不要補你覺得應該有的事項
- 不確定屬於哪一類，就放進「待確認」
- 最後另外列一段「我不確定的地方」給我看
同一段筆記，它從「編出一堆合理但根本沒講過的待辦」
變成「老實承認這裡我不知道」—— 差別只在這四行

**講稿**：現場示範：先用沒有這幾條規則的版本跑一次，讓他們看到它編東西；加上規則再跑同一段，對照差別。這是整堂課最有說服力的一個 before/after。


## Slide 23

裝完之後：調參數讓它更穩
23
跟 Codex 說：
「把 temperature 設成 0.2，max_tokens 設成 1200」
 
temperature  沒設的話預設是 1，調低 = 每次結果更穩、少亂發揮
max_tokens   輸出上限，避免它寫成一篇論文
model        現在用 llama-3.3-70b-versatile，免費又快
輸出格式每次都跑掉 → 先叫它把 temperature 調到 0.2，不是換 model
答案被截斷 → 叫它把 max_tokens 加大
真的需要更強的推理 → 才叫它換更大的 model（會變慢）

**講稿**：順序很重要：先調 temperature 再考慮換 model。新手一遇到問題就想換更大的 model，多數時候調參數就解決了，而且免費。
